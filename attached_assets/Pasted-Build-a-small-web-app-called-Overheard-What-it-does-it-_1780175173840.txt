Build a small web app called Overheard.

What it does: it watches public social conversations for people describing a
specific problem, and surfaces the best matches as a clean digest to a small
team. It does NOT auto-reply — humans read the digest and decide whether to
respond. Think "a smart, AI-filtered alert digest," not a posting bot.

Tech stack (match exactly; the app must be deployable to Render):
- Backend: Django + PostgreSQL (use DATABASE_URL).
- Frontend: plain HTML, CSS, and vanilla JS only — no React, no Tailwind, no framework.
- Production-ready: gunicorn, requirements.txt, all secrets via environment variables.
- Use Django management commands for scheduled work, so Render cron jobs can run them.

Core flow to implement (this is a two-stage funnel — keywords are a cheap net,
the AI is the real filter):

1. Onboarding: a simple page where the user pastes a website URL. The backend
   fetches that page's text and asks the Claude API to return (a) a short
   "relevance rubric" — the problem, who has it, the intent signals to look for,
   and examples of what looks relevant but isn't; and (b) a list of search
   queries/keywords. Save both as a Topic config the user can edit.

2. Fetchers:
   - Reddit: use the Reddit API (OAuth "script" app) to run the queries and pull
     recent posts and comments, time-filtered to roughly the last day. Free tier
     — respect rate limits and send an honest User-Agent.
   - X: use the X API v2 recent-search endpoint. Build this as a separate,
     OPTIONAL module: if X credentials are missing or the endpoint returns an
     access error, log it clearly and keep running on Reddit alone. The app must
     be fully functional with Reddit only.

3. Intent filter: for each new candidate, make one Claude API call that scores it
   against the rubric and returns JSON:
   { score 0-100, why_relevant, what_theyre_asking, suggested_angle }.
   Keep only items above a configurable score threshold. Run the AI only on
   fetched candidates, never on a broad firehose.

4. Storage: a model for matched items with platform, source URL, author, text
   snippet, the AI fields above, a status (new / replied / ignored), a timestamp,
   and a unique dedup key (platform + post id) so nothing is stored or shown twice.

5. Scheduler: a management command (e.g. `poll`) that runs fetch → filter → store,
   meant to run on a schedule. A second command (e.g. `send_digest`) composes and
   sends the digest.

6. Digest + notifications: compose a clean, pleasant digest of the top new items
   (each with one line on why it matters, what they're asking, and a link), and
   send it via email (SMTP, configurable) and Slack (incoming webhook). Mark items
   as sent.

7. Dashboard: one simple page listing recent high-relevance items with their
   why/angle and links out, plus buttons to mark an item "replied" or "ignored."
   Plain HTML/CSS/JS.

Environment variables (set up as secrets):
ANTHROPIC_API_KEY, REDDIT_CLIENT_ID, REDDIT_CLIENT_SECRET, REDDIT_USER_AGENT,
X_BEARER_TOKEN (optional), SLACK_WEBHOOK_URL, SMTP settings, DATABASE_URL.

How to work:
- Build incrementally and keep something working at every step. Suggested order:
  scaffold Django + models, then Reddit → filter → store → dashboard end to end,
  then the email/Slack digest, then the URL-to-rubric onboarding, then the X
  module. We want both Reddit and X in the end — just sequence so the app always runs.
- Keep it simple but robust: dedup, sensible error handling, rate-limit respect.
  Don't over-engineer or add features beyond this spec.
- Only use official APIs. Never scrape.
- If a specific API detail is uncertain, use the documented standard endpoint and
  leave a clear, labeled TODO plus a config option rather than guessing.
- Write clean, conventional Django so the project is easy to hand off and continue
  elsewhere later.

Start by proposing a brief plan and the data model, then build.
